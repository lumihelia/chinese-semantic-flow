# 错误分类（暂定 v1）

这张表根据仓库规范整理常见的错误类型，用来给案例打标签、检查覆盖面。九个标签不是互相排斥的九种“病”，也不用来算加权总分。一处具体的语义损害可能同时涉及几条规则；报告时先写出最小的那处损害，再打标签，避免重复计分。

| 标签 | 判定需要的证据 | 主要维度 / 仓库依据 | 必须保持通过的对照题 |
| --- | --- | --- | --- |
| unsupported_contrast | 被回应的 A 没有给定的、或允许使用的来源 | grounding, relation；SKILL §§0/1/16 | 有明确 A 的纠正；单纯陈述否定事实 |
| unsupported_detail | 候选新增了一个无法追溯来源的事实、观察者、机制或事件 | grounding；§§5/6/7 | 已给出具体资料；题目要求的虚构；明确可撤回、与资料相称的候选解释 |
| relation_drift | 能指出的因果、条件、并列、包含、先后或范围关系发生了变化 | relation；§3 | 必要的连接词；有证据的三项并列；真实存在的张力 |
| stance_drift | 作者的确定程度、知道的时间、经验范围、归属或立场变了 | stance；§§13/14 | 保留强判断；保留原有的犹豫；原样保留（KEEP） |
| interaction_overreach | 当前请求和材料不足以支持补上的情绪、动机、分析或选择 | grounding, task_fit；§§7–11 | 对方明说的情绪；明确的分析或建议请求 |
| task_mismatch | 候选缺少本轮必需的信息或动作，或者违背了具体要求 | task_fit；§§11/18/20–22 | 简短地完成任务；题目要求的总结、术语、列表或较长分析 |
| scope_leak | 用了没有加载的作者或 persona 约定，或者让 extension 压过了保真 | scope；第七部分、分层 A–E | 只加载 core 时的多种正常表达；已加载 profile 的局部约定 |
| template_overcorrection | 只为了避开某种词形或模板，删掉了本来有用的信息或功能 | 看实际损害落在哪个维度；§§4/4.1/15–19 | 正常的被动、所有格、第二人称、术语、总结、否定、对象前置 |
| unresolved_naturalness | 只有语感上的差别，缺少能分辨语域、上下文或作者偏好的证据 | discourse；§4.1、升级检查 | 弃权；保真任务下两个都足够好的版本可以判 tie |

`template_overcorrection` 描述的是一种对成因的推测，不能只看输出就断定生成者真的用了某条禁令。`unresolved_naturalness` 描述的是“还不知道”，不能累计成候选的失败。自动程序只检查标签是否合法、覆盖是否完整，不判断语义。

## 还没覆盖到的

现有数据覆盖单句改写、短对话，条件、因果、时间、并列、冲突和包含关系，有限的 profile 切换，以及历史参考答案的复核。还没有覆盖：

- 长篇里的话题链、段落重排与多轮对话的关系连续；
- 同一题目跨作者、跨地区、跨语域，以及面向真实读者的任务；
- 来源强弱不同、来源互相矛盾、引语归属、编辑授权一步步变化；
- 同时加载多个 extension，以及它们和任务自身规则的冲突；
- 作者文风 extension 的长文推进偏好、persona 安抚行为的明确请求边界；
- 真实 prompt 下有无 core 的生成对照，以及成本和模型版本；
- 控制语义之后，对信息顺序做盲选和复测；
- 独立的人工标注、一致性分析、争议裁决，以及真正没见过的测试题。

下一轮新增案例时，按题族和源材料整体切分。不要把本轮开发用的案例稍加改写就当成没见过的测试集，也不要因为合成的覆盖表填满了，就声称覆盖了真实的分布。
