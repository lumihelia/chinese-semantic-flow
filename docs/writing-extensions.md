# 怎样写 extension

本仓库只发布 core。作者文风、persona 或特定场景的规则，写成 extension，由使用者自己维护。

## 什么时候写 extension

一条规则只对某位作者、某个品牌、某个对话 persona 或某类场景成立时，写进 extension，不放进 core（见 [`rule-taxonomy.md`](./rule-taxonomy.md) 的 D、E 层）。例如：

- 性别未知时的代词约定；
- 某位作者写长文的推进方式，比如从个人经验走向公共判断；
- 某个 persona 的语气、俏皮与安抚的分寸；
- 某类产品文案的固定语体。

## 写什么

一个 extension 是一份 markdown，建议包含：

1. **适用范围**：属于谁、在什么场景加载、什么时候不加载；
2. **规则**：每条都写判断标准，不写词表禁令；
3. **正例、反例与成立的反例**：成立的反例说明原来的表达什么时候其实没问题；
4. **来源状态**：作者明确确认、只观察到一次，还是 Agent 的推断；推断一律标为候选；
5. **与 core 的关系**：改变了 core 的哪条默认，哪些 core 规则仍然优先（证据边界、用户当前指令始终优先）。

## 加载

宿主同时加载 core 和当前任务明确需要的 extension。几个 extension 同时适用、互相冲突时，按 `rule-taxonomy.md` 的冲突优先级裁决。

## 隐私

extension 常常引用作者的真实文字与校准记录。公开发布前，先确认引用的原稿、对话与校准记录都得到了作者同意；否则只发布规则本身，把证据留在私有的地方。
