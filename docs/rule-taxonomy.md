# 规则分层

中文 · [English](./rule-taxonomy.en.md)

Chinese Semantic Flow 按两件事给规则分层：它适用于多大范围，证据到了什么程度。一次稳定的“味道不对”可以成为候选规则，但不会自动变成普遍的中文规律。

## A 层：核心语义规则

跨作者、跨体裁都应当优先成立的语义判断：

- 先确定真正需要表达的命题；
- 保留事实、推断、不确定性与示例之间的区别；
- 具体化不能脱离证据；
- 因果、条件、时间、并列、包含和冲突，按真实关系进入语言；
- 改写不偷偷改变作者立场。

## B 层：中文表达规则

与中文生成习惯直接相关，并且可以被反例推翻：

- 语义连续比机械的连接词脚手架更重要；
- 动作、时间、因果和上下文足以承载关系时，允许意合；
- 转折和对照处理的 A 要能指向文本依据，说不出依据时直说 B；
- 中文能自然推进时，不机械保留英文的论证骨架。

某个结构经常被模型滥用，不等于它本身被禁止。

## C 层：互动规则

对话与解释中的通用边界：

- 信息不足时，不替对方补情绪或动机；
- 不用过早的 A/B 选项收窄对方还没说完的话；
- 解释保持可撤回；
- 回复密度跟随互动阶段；
- 判定权与自我定义留给当事人。

## D 层：场景规则

只有特定场景需要、可以跨作者复用的规则，例如：

- 个人随笔的推进方式；
- 系统层面的分析；
- 产品、品牌或 AI 的解释；
- 对话里的俏皮。

这些规则不默认加载。

## E 层：个人文风与 persona

属于特定作者、品牌或对话 persona 的规则，例如某位作者的代词约定、长文运动，或某个对话 persona 的语气与互动边界。本仓库不包含这一层的实例，写法见 [`writing-extensions.md`](./writing-extensions.md)。

E 层规则不能悄悄升级进 core。

## 冲突优先级

规则之间发生冲突时，按以下顺序裁决：

1. **用户当前指令与证据边界**，并列最高。指令决定任务和授权范围，证据边界决定什么能写成事实。明确要求虚构或举例时，可以放开细节（csf-004），但放开的内容要看得出来，不能冒充事实。
2. **保持作者的立场与判断**。
3. **任务本身的功能**，包括对话密度（§11）。
4. **中文表达规则**（B 层）。
5. **风格偏好与 extension**（D、E 层）。

自检清单和对话密度并不冲突：自检是写作者的检查，不是输出内容，短回复只跑对话那一层。

作者文风 extension 里常有“保留半成型思想”一类规则，它和 core §5 的“机制先于口号”看起来相反。裁决看两件事：思想属于谁，文本拿来做什么。编辑作者的文本时，不替作者补机制；生成的文本要让读者据此判断或行动时，追问机制；生成的文本是在呈现思考过程时，保留半成型，但写成未完成。私人还是公开，不是判断标准。

## 升级检查

一个新观察通常沿这条路径走：

> “味道不对”的反应 → 说清楚 → 候选规则 → 正例与反例 → 边界条件 → 回归案例 → 反复验证 → 可能升级

升级一条规则之前，先问：

1. 这个问题属于语义、中文表达、互动，还是个人文风？
2. 它能不能跨作者、跨例子成立？
3. 它会误伤哪些本来没问题的表达？
4. 它更适合写成有条件的检查，还是明确的禁止？
5. 有没有成立的反例能划出边界？
6. 能不能写成具体的回归案例？

## 降级与迁移

规则也可以往下走。

如果发现一条 core 规则其实只适用于某位作者、某个 persona 或某种场景，就把它迁到 extension，不为了历史稳定硬留在 core。

v0.2 做的主要就是一次迁移：命题、证据、判定权这些可以迁移的判断留在 core；某位作者的长文运动、代词约定、persona 的俏皮、动态的自我理解，以及“从可能到现实”这类母题，迁回各自的 extension。

## 设计立场

Chinese Semantic Flow 是一套可以修订的判断系统，它不规定中文应该怎么写。

它要让生成更忠实于思想、证据、语境和对方的判定权，同时让每条规则都留有反例和修订的余地。
